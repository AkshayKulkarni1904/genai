      ⚡ 2-Minute Quick Revision Cheat Sheet
      
              13 Modules at a Glance
            
      
            
      
              
              
      
                
      M01Foundations
      
                
      Foundations of GenAI & LLMs
      
                
      Purpose:
      Understand how LLMs generate text and how model parameters govern generation.
      
                
      Key Concepts:
      Tokens • Context Windows • Temperature • Top-p • Max Tokens • Hallucination • Grounding
      
                
      Practical:
      Parameter sandbox analyzing latency, cost, and entropy trade-offs.
      
                
              
      

              
      
                
      M02Foundations
      
                
      Prompt Engineering
      
                
      Purpose:
      Control model behavior reliably through structured, tested and defensive prompts.
      
                
      Key Concepts:
      Zero/Few-Shot • Role Prompting • Chain-of-Thought • JSON Schema • Defensive Guardrails
      
                
      Practical:
      Support ticket classification, contract clause extraction & business rule audit.
      
                
              
      

              
      
                
      M03Foundations
      
                
      Using LLM APIs in Programming
      
                
      Purpose:
      Turn an LLM into a resilient, production-grade application component.
      
                
      Key Concepts:
      Exponential Backoff • Failover Router • Function Calling • Streaming Deltas • Cost Logging
      
                
      Practical:
      Resilient client with multi-provider failover, tool calling & usage tracking.
      
                
              
      

              
      
                
      M04Foundations
      
                
      Direct API vs LangChain
      
                
      Purpose:
      Choose abstraction based on architectural complexity, not because a framework exists.
      
                
      Key Concepts:

      🔍 Detailed Module-by-Module Revision & Concept Rationale
      
                
      Expand any module to review detailed concepts, practical deliverables, and "Why these concepts?" micro-explanations.
      
              
      
              
      
                
                
              
      
            
      

            
            
      
              
                
      
                  M01
                  Foundations of Generative AI and LLMs
                
      
                Foundations
                    
              
      
                
      Understand what LLMs are, how they generate text, and how model parameters influence generation.
      
                
      
                  
      
                    What You Learn
                    
      Next-token prediction mechanics, BPE tokenization, context window budget constraints, entropy vs determinism, and latency/cost economics.
      
                  
      
                  
      
                    Why It Exists
                    
      Establishes the foundation for understanding LLM behavior, limitations, reliability, cost, latency and enterprise concerns.
      
                  
      
                
      
                
      
                  
      💡 Why These Concepts?
      
                  
      Why Tokens? → Models do not process words; they process BPE token IDs which directly determine billing, latency, and context limits.
      
                  
      Why Temperature & Top-p? → Controls the probability distribution tail during decoding to balance analytical precision vs creative variation.
      
                  
      Why Grounding? → LLMs possess internal parametric memory; grounding forces answers to rely on external evidence rather than hallucinated facts.
      
                
      
                
      "Understand the model before building systems around the model."
      
                
      
                  Practiced: Basic text-generation application & parameter sensitivity lab.
                  
                
      
              
      
            
      

            
            
      
              
                
      
                  M02
                  Prompt Engineering Studio
                
      
                Foundations
                    
              
      
                
      Learn how to design, structure, evaluate and defend prompts for different enterprise tasks.
      
                
      
                  
      
                    What You Learn
                    
      Anatomy of system/developer/user prompts, few-shot conditioning, chain-of-thought step-by-step reasoning, JSON schema enforcement, and prompt injection defense.
      
                  
      
                  
      
                    Why It Exists
                    
      Good prompting controls how reliably an LLM performs classification, extraction, summarization, rewriting and decision-support tasks.
      
                  
      
                
      
                
      
                  
      💡 Why These Concepts?
      
                  
      Why Few-Shot Examples? → Guides the model toward the exact output format and edge-case handling without expensive fine-tuning.
      
                  
      Why Chain-of-Thought? → Giving the model intermediate tokens to "think" significantly reduces arithmetic and logical errors.
      
                  
      Why Defensive Instructions? → Untrusted user input can hijack model instructions (prompt injection); delimiters and negative constraints safeguard execution.
      
                
      
                
      "Control model behavior through structured, tested and defensive prompts."
      
                
      
                  Practiced: Ticket triage classification, contract data extraction & business rule auditing.
                  
                
      
              
      
            
      

            
            
      
              
                
      
                  M03
                  Using LLM APIs in Programming
                
      
                Foundations
                    
              
      
                
      Learn how to integrate LLMs into real applications through APIs.
      
                
      
                  
      
                    What You Learn
                    
      API authentication, rate limit mitigation, retries with exponential backoff, fallback provider routing, function/tool calling dispatch, streaming SSE, and token cost telemetry.
      
                  
      
                  
      
                    Why It Exists
                    
      Moves from experimenting with LLMs in web UIs to building resilient, scalable software around them.
      
                  
      
                
      
                
      
                  
      💡 Why These Concepts?
      
                  
      Why Exponential Backoff? → Prevents thundering-herd API lockouts when rate limits (HTTP 429) or transient network timeouts occur.
      
                  
      Why Failover Models? → Frontier models occasionally suffer outages; having an automated secondary provider prevents system downtime.
      
                  
      Why Tool Calling? → Allows the LLM to trigger real deterministic functions (DB queries, calculations, ServiceNow updates) rather than fabricating answers.
      
                
      
                
      "Turn an LLM into a reliable application component."
      
                
      
                  Practiced: Resilient API assistant with JSON validation, fallback routing & usage monitoring.
                  
                
      
              
      
            
      

            
            
      
              
                
      
                  M04
                  Direct LLM API Calls vs LangChain
                
      
                Foundations
                    
              
      
                
      Understand when direct API calls are better and when LangChain provides useful abstractions.
      
                
      
                  
      
                    What You Learn
                    
      Comparing code simplicity, execution latency, dependency foot-print, debugging overhead, and framework lock-in vs rapid prototyping value.
      
                  
      
                  
      
                    Why It Exists
                    
      Prevents unnecessary framework complexity and helps architects make informed architectural decisions.
      
                  
      
                
      
                
      
                  
      💡 Why These Concepts?
      
                  
      When Direct API? → Simple, low-latency, mission-critical microservices where stack trace transparency and minimal dependencies are required.
      
                  
      When LangChain? → Complex multi-step pipelines involving diverse document loaders, vector stores, output parsers, and agentic tools.
      
                
      
                
      "Choose abstraction based on complexity, not because a framework exists."
      
                
      
                  Practiced: Side-by-side document Q&A implementation benchmarking latency and call depth.
                  
                
      
              
      
            
      

            
            
      
              
                
      
                  M05
                  Embeddings and Vector Search
                
      
                Retrieval
                    
              
      
                
      Learn how text becomes embeddings and how semantic search retrieves relevant information.
      
                
      
                  
      
                    What You Learn
                    
      Chunking algorithms (Fixed, Recursive, Document-aware), Cosine vs Dot Product vs Euclidean distance, vector index schemas, metadata filtering, and Hybrid Reciprocal Rank Fusion (RRF).
      
                  
      
                  
      
                    Why It Exists
                    
      Provides the retrieval foundation required for all modern RAG systems.
      
                  
      
                
      
                
      
                  
      💡 Why These Concepts?
      
                  
      Why Chunking? → Raw documents are too large for semantic precision; chunking creates focused, retrievable semantic context units.
      
                  
      Why Cosine Similarity? → Evaluates directional alignment in high-dimensional embedding space regardless of token length disparities.
      
                  
      Why Hybrid Search (RRF)? → Combines dense semantic recall with exact keyword precision (e.g. part numbers, error codes).
      
                
      
                
      "Convert knowledge into searchable representations."
      
                
      
                  Practiced: Semantic search over policy documents with metadata filters & chunking visualizer.
                  
                
      
              
      
            
      

            
            
      
              
                
      
                  M06
                  Retrieval-Augmented Generation (RAG)
                
      
                Retrieval
                    
              
      
                
      Understand how retrieval supplies external knowledge to an LLM before generation.
      
                
      
                  
      
                    What You Learn
                    
      End-to-end RAG architecture: ingestion, query rewriting, multi-tenant RBAC permissions gating, cross-encoder reranking, context assembly, and citation provenance.
      
                  
      
                  
      
                    Why It Exists
                    
      Reduces dependence on model memory and enables grounded answers from live enterprise documents.
      
                  
      
                
      
                
      
                  
      💡 Why These Concepts?
      
                  
      Why Query Rewriting? → Multi-turn chat contains ambiguities ("it", "the previous error"); rewriting creates standalone search queries.
      
                  
      Why Rerankers? → Bi-encoders are fast but coarse; cross-encoders re-score top candidates for true passage relevance.
      
                  
      Why Citations? → Guarantees transparency and auditability so enterprise users can verify claims against sources.
      
                
      
                
      "Retrieve the right evidence before asking the LLM to answer."
      
                
      
                  Practiced: Enterprise knowledge assistant for HR policies & support articles with RBAC.
                  
                
      
              
      
            
      

            
            
      
              
                
      
                  M07
                  Advanced RAG Patterns
                
      
                Retrieval
                    
              
      
                
      Move beyond basic RAG to complex retrieval, reasoning and enterprise data patterns.
      
                
      
                  
      
                    What You Learn
                    
      Parent-child chunking, multi-vector representations, Corrective RAG (CRAG) grading, SQL fallback routing, and semantic LRU caching.
      
                  
      
                  
      
                    Why It Exists
                    
      Basic vector retrieval is not sufficient for complex enterprise questions and heterogeneous data.
      
                  
      
                
      
                
      
                  
      💡 Why These Concepts?
      
                  
      Why Parent-Child Retrieval? → Small child chunks optimize vector search precision, while parent documents provide complete context to the LLM.
      
                  
      Why Corrective RAG (CRAG)? → An evaluator grades retrieved document relevance; if low, it halts generation and triggers a web/SQL fallback.
      
                  
      Why Semantic LRU Cache? → Avoids redundant LLM & embedding API calls for recurring queries, slashing latency to under 5ms.
      
                
      
                
      "Make retrieval adaptive, structured and enterprise-ready."
      
                
      
                  Practiced: Support-resolution assistant combining docs, resolved tickets & customer configs.
                  
                
      
              
      
            
      

            
            
      
              
                
      
                  M08
                  Knowledge Graph Fundamentals
                
      
                Knowledge Graphs
                    
              
      
                
      Learn how enterprise information can be represented as entities and relationships.
      
                
      
                  
      
                    What You Learn
                    
      Nodes, labeled edges, properties, enterprise ontology schemas, Cypher pattern queries, entity resolution, and graph governance.
      
                  
      
                  
      
                    Why It Exists
                    
      Some business knowledge is better represented through relationships than isolated document chunks.
      
                  
      
                
      
                
      
                  
      💡 Why These Concepts?
      
                  
      Why Explicit Relationships? → Vector search sees similarity, not semantics; graphs explicitly state `[User]-[:EXPERIENCED]->[Incident]`.
      
                  
      Why Cypher? → Provides declarative, deterministic pattern traversal that traverses multi-hop dependency chains without guessing.
      
                  
      Why Entity Resolution? → Maps multiple naming variants ("K8s", "Kubernetes", "k8s-prod") to a single canonical entity node.
      
                
      
                
      "Represent connected knowledge explicitly."
      
                
      
                  Practiced: IT support graph connecting Users, Devices, Apps, Incidents, Teams & Resolutions.
                  
                
      
              
      
            
      

            
            
      
              
                
      
                  M09
                  GraphRAG Studio
                
      
                Knowledge Graphs
                    
              
      
                
      Combine graph relationships with retrieval to answer complex connected questions.
      
                
      
                  
      
                    What You Learn
                    
      Vector RAG vs GraphRAG trade-offs, hierarchical community detection (Leiden), multi-hop graph traversal, root-cause investigation, and global query summarization.
      
                  
      
                  
      
                    Why It Exists
                    
      GraphRAG is useful when relationships, dependencies, multi-hop reasoning and root-cause analysis matter.
      
                  
      
                
      
                
      
                  
      💡 Why These Concepts?
      
                  
      Why Community Detection? → Clusters closely related entity neighborhoods into summaries, enabling macro-level answers to broad questions.
      
                  
      Why Multi-Hop Traversal? → Follows relationship chains (e.g. Service A depends on DB B which triggered Alert C) across multiple silos.
      
                
      
                
      "Use graphs when relationships are part of the answer."
      
                
      
                  Practiced: 4-step GraphRAG incident-resolution workflow with community summarization.

      💡 Why These Concepts?
      
                  
      Why LCEL Pipe Syntax? → Standardizes streaming, async batching, and error handling across heterogeneous components.
      
                  
      Why Pydantic Parsers? → Automatically converts unstructured text into strictly typed, validated Python data models.

      Learn how to build stateful, controllable agent workflows.
      
                
      
                  
      
                    What You Learn
                    
      StateGraph nodes and edges, state reducers, conditional routing, cyclic execution, persistence checkpoints, interrupt signals, and ServiceNow API actions.
      
                  
      
                  
      
                    Why It Exists
                    
      Useful when applications require branching, loops, retries, persistence and human approval.
      
                  
      
                
      
                
      
                  
      💡 Why These Concepts?
      
                  
      Why Cycles & Loops? → Real agentic reasoning requires trying an action, inspecting the error, and looping back to correct it.
      
                  
      Why Checkpointing? → Persists agent memory across long-running asynchronous human approvals or server restarts.
      
                  
      Why Human-in-the-Loop? → Prevents autonomous execution of high-risk actions (e.g. database deletes, ticket closures) without human oversight.

                  M13
                  Evaluation, Guardrails & Production Readiness
                
      
                Evaluation & Governance
                    
              
      
                
      Learn how to evaluate GenAI systems and make them safe, observable and production-ready.
      
                
      
                  
      
                    What You Learn
                    
      Golden datasets, Precision & Recall metrics, LLM-as-a-Judge grading, PII detection & redaction, role-based retrieval, and prompt injection defense.
      
                  
      
                  
      
                    Why It Exists
                    
      A GenAI system is not production-ready simply because it generates good responses in an isolated demo.
      
                  
      
                
      
                
      
                  
      💡 Why These Concepts?
      
                  
      Why Golden Datasets? → Establishes reproducible ground truth to measure whether prompt or code changes cause regression.
      
                  
      Why LLM-as-a-Judge? → Evaluates subjective qualities (faithfulness, clarity, safety) faster and more consistently than manual review.
      
                  
      Why PII Redaction? → Ensures sensitive data (emails, credit cards, SSNs) never leak into external LLM logs or vector stores.
      
                
      
                
      "Measure, protect, observe and continuously improve the GenAI system."
      
                
      
                  Practiced: 50 golden queries evaluation benchmark & real-time guardrails interceptor.
